# Network surfaces, routing and limits
Local adapter fixed origins only: `data-api.binance.vision`, `fapi.binance.com`, `api.llama.fi`, `api.dexscreener.com`, `mempool.space`; GET only, TLS verification, no redirects, URL/path allowlisting, bounded responses and input validators. This is adapter-layer allowlisting, **not** OS-wide network egress enforcement. Other remote MCPs in global config have independent network/credential behavior; provider server metadata is not authority. Use a tested network proxy or OS isolation for an enforceable host-wide allowlist. Respect region restrictions and 429/Retry-After; never rotate IPs or hostnames to evade limits. Requests to missing or restricted endpoints fail with explicit status. HTTP caching and window limits are project implementation behavior, not upstream freshness promises.
