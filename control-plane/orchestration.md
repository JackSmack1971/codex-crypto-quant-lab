# Bounded task DAG
Supervisor identifies decision question and evidence windows, checks tool capability registry, then fans out at most three independent investigations by domain: spot/derivatives, onchain/DeFi, and official/source verification. Each worker returns typed provenance + failure/unknown ledger. A synthesis barrier merges only definitionally compatible data; alternatives are context not drop-in equivalents. Methodology reviewer adversarially checks time alignment, sample bias, nulls, lookahead and claims; report editor drafts final local deliverable. A verifier checks actual citations and generated artifacts. No nested delegation. Native Codex roles are behavioral threads sharing parent permission/MCP state, not independently sandboxed processes or worktrees. Subagent disagreements are resolved by sources/tests, never majority vote.

## Hypothesis competition (optional, evidence-led)
For conflicting crypto explanations, supervisor predefines alternatives, falsifiers and essential metric coverage. Delegate bounded source gathering using existing roles; synthesize at one barrier. `crypto-hypothesis` consumes explicit evidence assignments; no role is a vote and no duplicate observation is independent corroboration. Use `research_lab.evaluate_hypothesis` only after source-quality and instrument-compatibility checks. The methodology reviewer assesses contradictory and missing evidence. Do not add a second LLM orchestration runtime. See `research-lab.md`.


## Research experiment path (v2.3)
Only after a source-quality synthesis barrier, use the `crypto-strategy-lab` Skill to bind verified observations to deterministic models and a declared `StrategySpec`. `crypto-temporal-validation` checks time windows and selection bias; the independent methodology reviewer inspects actual folds, evidence timing, incompatible metrics, and hypothetical cost assumptions. Persist locally via `EvidenceArchive` and `TransactionalResearchLedger`, and retain separately anchored tip receipts when audit requirements justify them. Do not treat research signals as executable positions, automated trading recommendations or authorizations.

## Research committee contract (v2.4)

An analytical committee is a *task DAG*, not another agent runtime or permanent set of personas. The primary Codex supervisor defines one decision question, as-of UTC, instrument and venue identities, mandatory evidence, shared-source dependency risks, and explicit falsifiers. Delegate only when the question has independent branches:

1. `market_researcher`: spot/derivatives and cross-asset observations with timestamped source identities.
2. `onchain_researcher`: chain/network observations with entity-attribution limitations.
3. **Synthesis barrier:** reconcile source overlap, vendor dependencies, conflicting data and definition mismatches before conclusions.
4. `source_verifier`: adjudicate missing primary sources, quote accuracy, availability and provenance.
5. `methodology_reviewer`: challenge selection bias, label leakage, cost assumptions and inferential leaps; record dissent as evidence-linked hypotheses.
6. `report_editor`: prepare the local evidence-bound report; the supervisor owns final verdict and stop/go criteria.

Bull and bear briefs are task assignments within these roles, not votes. Max three independent concurrent investigative workers; no nested fan-out; one author owns any overlapping mutable artifact. Every worker supplies `task_id`, exact input baseline, observed source/UTC, unknowns, method, conflicts and evidence IDs. A committee cannot convert absent data into consensus. Use `research_lab.evals.evaluate_task` to grade saved artifacts; only a runtime can attest what tools were actually used.

**Durable jobs:** `research_lab.jobs.JobStore` records task transitions. A recovered `RUNNING` job is *not* `COMPLETED`; reconcile local files, database rows and downstream effects before moving `INTERRUPTED → RECONCILING → RUNNING`. No automatic retries of non-idempotent actions. Job records do not create Codex sessions or authorize external effects.

## Durable mission execution (P1)

`research_lab.mission_coordinator.MissionCoordinator` (CLI: `python scripts/mission.py --workspace DIR create|status|advance|resume|cancel`) executes a `research-mission-execution.v1` specification through fixed stages `PLANNED -> ACQUIRING -> RECONCILING -> ANALYZING -> VERIFYING -> RENDERING -> FINALIZING`. It is a deterministic local engine layered on `JobStore`, **not** another orchestration framework: it never invokes Codex agents, providers, shells or the network, has no scheduler or service, and a mission state is never authorisation for an external effect. Native Codex roles keep their existing contract; they may write `reviewer-handoff.v1` JSON (`reviewer`, `state` of `PASS`/`FAIL`/`NOT_PERFORMED`, `evidence` ids, optional `produced_by`) that the spec pins by path and SHA-256. An undeclared, invalid, or `PASS`-without-eligible-evidence handoff is recorded as `NOT_PERFORMED`; a declared but absent handoff leaves the `VERIFYING` stage `BLOCKED` (job stays `RUNNING`) until it appears. The coordinator never writes a review `PASS` itself.

Execution state and scientific state are separate. Job lifecycle (`NEW/RUNNING/INTERRUPTED/RECONCILING/COMPLETED/FAILED/BLOCKED/CANCELLED`) and per-stage status (`PENDING/RUNNING/SUCCEEDED/FAILED/BLOCKED/SKIPPED`) describe the process; `research_state` (`NOT_EVALUABLE/INSUFFICIENT_EVIDENCE/EVALUABLE`) describes the evidence and is never `VALIDATED` here. Stage `RECONCILING` (source reconciliation) is unrelated to job state `RECONCILING` (crash recovery). `COMPLETED` means the bundle verified as `COMPLETE` **and** the research state is among the spec's `accepted_research_states`; an `INSUFFICIENT_EVIDENCE` outcome is a legitimate completed mission when accepted. Anything else ends `BLOCKED` with a stable code (`REQUIRED_EVIDENCE_UNAVAILABLE`, `COMPLETION_REQUIREMENT_UNMET`, `VERIFICATION_FAILED`) and the bundle documenting why. Provider operations are only *recorded*: a declared operation without a caller-supplied runtime record is `UNATTEMPTED`, and supplied records are labelled unauthenticated.

Recovery is explicit. `advance_mission` never resumes a stage it finds `RUNNING`; it returns `RECOVERY_RECONCILIATION_REQUIRED`. `reconcile_mission` takes over the claim (bumping a fence so a stale executor cannot commit), recomputes the stage's deterministic operation, classifies on-disk artifacts as `ABSENT`/`PARTIAL`/`COMPLETE`/`CONTRADICTORY`, and then adopts verified output, completes missing files, or blocks with the contradictory evidence retained. Tampered or missing completed-stage outputs block the job (`STAGE_OUTPUT_DIGEST_MISMATCH`, `STAGE_OUTPUT_MISSING`). Run `reconcile_mission` only when no live executor owns the mission; fencing keeps results safe if it does, but work may be duplicated. SQLite and the filesystem are not one transaction, which is why reconciliation, not atomicity, is the recovery contract.

Mission-to-experiment link: a spec may declare `experiment: {experiment_id, registration_digest[, result_digest]}`. Only these pinned facts are accepted, so the `ANALYZING` operation stays a pure function of its inputs and recovery can replay it. An unregistered experiment, or a pinned result not yet recorded, blocks the stage (job stays `RUNNING`); a digest that differs from the pin fails it. Without `result_digest` the mission records the registration only and states that no holdout evidence is included; it never evaluates or consumes a holdout.

Provider-operation records: a caller-supplied `SUCCEEDED` record is accepted only if it cites `observation_ids` that were ingested from the pinned research-run input; a bare assertion is downgraded to `UNATTEMPTED` with `claimed_status: SUCCEEDED`. This links the claim to evidence but does not authenticate it: records and reviewer handoffs remain unauthenticated assertions.

Known operational limits: `cancel_mission` is unavailable while the job is `RECONCILING` (JobStore transition table); a mission that ended `BLOCKED` because reviewer handoffs were absent is terminal, so late handoffs require a new mission id (use `supersedes`); `reconcile_mission` cannot distinguish a dead executor from a live one, and each takeover consumes an attempt; output directories may not be equal to or nested within another mission's; the symlink/containment check is not atomic against a concurrent local writer with workspace write access.

## Benchmarks and history (P2)
`python scripts/benchmark.py [--cases ...] [--repeat N]` runs the offline `research-benchmark-case.v1` suite (see `benchmarks/`); expected outcomes are authored separately from the runner, a mandatory-dimension failure is never offset by passes elsewhere, and results make no predictive-performance claim. Rendering extends the P1 stage sequence without adding stages: `render.local_report@2` and `finalize.bundle@2`. Compatibility of `@1` renders: a mission whose `RENDERING` completed under `render.local_report@1` (outputs exactly `report.md`/`report.html`) is detected from the stage's recorded operation version (`MissionCoordinator.render_is_legacy`) and finalizes under that **declared v1 contract**: no companions, `mission_baseline.json` carries `render_contract: render.local_report@1`, and the shared companion verdict is `ABSENT_DECLARED_V1`. It is never reinterpreted as a v2 render, a v2 render never takes this path, and a stage claimed as `@1` whose committed outputs differ is refused (`RENDER_V1_OUTPUT_INVALID`). Missions not yet at `RENDERING` use `@2`; a mission interrupted *while* `RENDERING` is claimed is resumed by `reconcile_mission` under `@2` in a new, separately keyed directory. `reconcile_mission` never repairs a terminal job: for `FAILED`/`COMPLETED`/`CANCELLED` it returns `NOTHING_TO_RECONCILE` with the diagnostic `JOB_TERMINAL_NOT_REPAIRABLE`, and a mission that already failed in `FINALIZING` before this rule existed must be recreated under a new mission id (`supersedes`).

Holdout exposure (repair H1): `experiment_registry` records the normalised holdout interval hull per registration. A new registration or evaluation whose hull overlaps any exposed experiment (`EVALUATING`, `CONSUMED`, `INVALIDATED` or exposure_count > 0) on the **same dataset lineage** (same `dataset_id` *or* same full-dataset digest) is `HOLDOUT_ALREADY_EXPOSED`; a changed `experiment_id`, split or `dataset_version` never makes a holdout untouched. Overlap with a different dataset identity yields `independence: UNKNOWN` (`independent_evaluation` false). Disjoint holdouts on one lineage are `ESTABLISHED_LOCAL`. Rows written before this rule have no interval record and report `LEGACY_UNQUALIFIED` (`independent_evaluation` false; readable). Independence is relative to this local registry and is never proof of dataset independence or of independent samples. Qualification (final hardening): every `summary`/`evaluate` response keeps `independent_evaluation` (compatibility) and adds `independence_scope` and `independence_limitations`. `independence_scope` is `LOCAL_REGISTRY_RELATIVE` only when `independent_evaluation` is true (`ESTABLISHED_LOCAL`, one non-recovered, non-reused exposure) and means solely that no overlap was found against holdouts recorded in this registry under the declared `dataset_id` and full-dataset digest; it is `NOT_ESTABLISHED` for `UNKNOWN`, `LEGACY_UNQUALIFIED`, `PENDING_CLAIM`, recovered, reused or repeatedly exposed evaluations, which must never be described as independent. Shifted timestamps, a changed `dataset_id` or an altered digest on the same underlying data can defeat the declared lineage, and neither content equality nor inequality proves independent samples. The scope fields are additive; the registry schema is unchanged.

Timestamps (repair H2): observations are compared, grouped and ordered by semantic UTC instant (`core.instant_key`), not by spelling, so `…Z`, `…+00:00` and equivalent fractional seconds are one instant. Stored evidence keeps its original spelling (no digest change); an observation available before it was observed is excluded as `CHRONOLOGY_INVALID`.
